# Skill: Documentar requisitos

## Objetivo

Ayudar a documentar las funcionalidades de THE WOLF de manera clara, organizada, coherente y comprobable antes de implementar cambios en el código.

## Instrucciones

1. Consultar `AGENTS.md`, `memory.md`, `docs/CONSTITUCION.md` y los documentos relevantes de `docs/`.
2. Identificar la necesidad que se quiere resolver y el resultado esperado.
3. Revisar los requisitos existentes para evitar duplicaciones y contradicciones.
4. Distinguir entre:
   - Requisitos funcionales: describen lo que el sistema debe hacer.
   - Requisitos no funcionales: describen condiciones de calidad, seguridad, accesibilidad, rendimiento y mantenimiento.
5. Asignar identificadores consistentes, como RF12 o RNF08, sin reutilizar identificadores existentes.
6. Redactar criterios de aceptación objetivos que permitan comprobar el cumplimiento.
7. Considerar casos límite, validaciones, mensajes de error y comportamiento en dispositivos móviles cuando corresponda.
8. Registrar las dudas y decisiones pendientes en lugar de inventar información.
9. Respetar el alcance actual del proyecto: HTML, CSS y JavaScript para el sitio inicial.
10. No afirmar que existen una base de datos, un backend, pagos en línea u otras funciones que todavía no estén implementadas.
11. Proponer en qué documento de `docs/` debe registrarse cada cambio.
12. No modificar archivos sin autorización del usuario.

## Formato de salida

- Nombre del requisito.
- Identificador.
- Tipo: funcional o no funcional.
- Descripción.
- Justificación.
- Criterios de aceptación.
- Restricciones y casos límite.
- Dependencias.
- Dudas pendientes.
- Documento donde se recomienda registrarlo.

## Reglas del proyecto

- Escribir en español claro y consistente.
- Mantener la coherencia con la identidad y los objetivos de THE WOLF.
- Priorizar requisitos verificables y realistas.
- No confundir funcionalidades planificadas con funcionalidades implementadas.
